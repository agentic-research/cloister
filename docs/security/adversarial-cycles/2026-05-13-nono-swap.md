## Cross-cut findings (NEW this cycle)

### Cross-cut A — "Trust-boundary contract enforced at the binding, not at the call site"

Three independent specialists (trust-root F2, isolation F-iso-1,
implicit in dos F2) found the same structural gap: **POST /sign does
not consult an allow-list against the resolved URL**. Today, any
bearer-token holder can ask the helper to sign with `op://attacker/...`,
`apple-password://attacker/...`, `keychain://anything-on-the-keychain`,
etc. The `/resolve` surface has the gate (`LEYLINE_SIGN_RESOLVE_ALLOW`,
post-cycle-1); `/sign` does not. The trust boundary is enforced at
deploy time when the operator chose to set `VAULT_KEK_SOURCE`, but
that env var is consulted only by the *workerd-side* `HelperKekSource`
(`vault/src/kek-source.ts`) — the helper itself has no concept of
"signing-key URL allow-list."

Pre-swap this was already a gap but the reachable URLs were just
`keychain://...` and `secret-tool://...` (both reading from one
process-wide keyring crate against `KEYCHAIN_ACCOUNT`). Post-swap, the
reachable URLs include `op://` and `apple-password://`, which dispatch
to subprocesses that inherit the helper's env — full credential
laundering surface.

**Cross-cut prescription.** Mirror the `/resolve` allow-list to
`/sign` with **per-caller** binding: `LEYLINE_SIGN_SIGN_ALLOW` maps
`caller_name -> Vec<prefix>` and is consulted in `post_sign` after
auth, before `keystore::resolve_bytes`. Default deny-all with
`--require-sign-allow` flag analogous to `--require-auth`. This is
the same shape as cycle-1's §15.2 close (per-caller bearer-token
auth) — same discipline, different axis. ADR-0019 normative
requirements get a new req 14: "Helper MUST refuse `/sign` for URLs
not on a per-caller allow-list when `--require-sign-allow` is set."

Source findings: trust-root F2 (P0), isolation F-iso-1 (P1; same
underlying issue, scored P1 because isolation-friend's lens didn't
weight the subprocess-laundering chain).

### Cross-cut B — "Blocking calls on async runtimes pin worker threads"

dos-friend F1 + silence-friend Gap 2 converge: `nono::keystore::load_secret_by_ref`
is fully synchronous (blocking `std::thread::sleep(100ms)` polling
loop inside `wait_with_timeout` for `op` / `security` subprocesses,
with `SECRET_MANAGER_TIMEOUT = 30s`), and `read_keystore_string_with_trim`
calls it **directly on the tokio worker thread** — no
`spawn_blocking`. The outer `tokio::time::timeout(SIGN_TIMEOUT, ...)`
fires at 5s and abandons the future, but the blocking call does not
yield. Worker threads stay pinned for 30s; orphaned `op` / `security`
subprocesses accumulate.

This is the most exploitable finding of the cycle — N+1 concurrent
`/sign` calls against an `op://` URL (where N is the tokio worker
thread count, default `2 * num_cpus`) effectively DoS the helper for
30s, with the helper's *own* rate limiter unable to help because the
attack uses the legal token-bucket allotment.

**Cross-cut prescription.** Wrap `nono::keystore::load_secret_by_ref`
in `tokio::task::spawn_blocking` inside
`read_keystore_string_with_trim`. This is a one-line fix that moves
the blocking poll to the dedicated blocking pool (default 512
threads). Combine with a `tokio::time::timeout(SIGN_TIMEOUT,
spawn_blocking(...))` to bound the request future. Note that the
orphaned subprocess still lives until nono's 30s timer fires — that's
nono's responsibility (file upstream issue) but doesn't block the
runtime.

Source findings: dos F1 (P0), silence Gap 2 (P0; same).

### Cross-cut C — "Error mapping discards diagnostics AND leaks wire bits"

silence-friend Gap 3 + oracle-friend F1/F2 converge: `map_nono_err`
collapses every `NonoError` to a `HelperError` variant without logging
the underlying diagnostic, AND the chosen variants (`KeystoreLocked`
for `KeystoreAccess`, `BadRequest` for `ConfigParse`) carry distinct
wire bodies that distinguish "absent" from "present-but-locked" from
"shape-wrong."

The fix collapses both ends: on the **wire**, route all of
`KeystoreAccess`, `ConfigParse`, and `_` to `HelperError::NotFound`
(byte-identical with the genuine absent path); in **tracing**, emit
a warn-level log with the nono diagnostic string (which is already
redacted by nono via `redact_*_uri`) and the outcome label
(`keystore_locked`, `bad_uri`, etc.) before the wire collapse.

Source findings: oracle F1 (P1) + F2 (P2), silence Gap 3 (P1).

### Cross-cut D — "Supply-chain attestation is a paper claim"

trust-root F1 + F4 + isolation F-iso-3: the swap pulls in
sigstore-verify, sigstore-trust-root, aws-lc-rs (with `aws-lc-sys`
bindgen-into-C), landlock, x509-cert, walkdir, ignore, globset,
regress, and ~74 other transitive crates. The previous ADR-0019
§"Implementation pins" line "Crate: `ed25519-dalek = '2.1'`" was the
documented trust base. Post-swap that line is incomplete.

Three independent attestation gaps:
1. **No `cargo audit` / `cargo deny` in CI.** A CVE in any of the new
   transitive crates lands silently.
2. **Toolchain pin `1.95.0` is in `rs/rust-toolchain.toml` but CI uses
   `toolchain: stable`.** A PR that deletes the pin would silently
   bump CI's toolchain.
3. **Subprocess env wholesale inherited.** Even with PATH pinned
   (trust-root F3 fix), `op` and `security` inherit `OP_SERVICE_ACCOUNT_TOKEN`,
   `OP_SESSION_*`, `HOME`, and any operator-tier vars the supervisor
   leaks. nono uses `Command::new(...).args([...])` without
   `.env_clear()` — and exposing an env-allowlist requires a nono
   patch or a cloister-side bypass shim.

**Cross-cut prescription.** Three actions, each closeable on this
branch:
1. Add `task rs:audit` (runs `cargo audit --deny warnings` +
   `cargo deny check`); fold into `task verify` so the strict CI gate
   exercises it. Existing `lint` stays fast (~2s).
2. Add a CI step asserting `rs/rust-toolchain.toml` matches the
   documented pin (`grep -q 'channel = "1.95.0"' rs/rust-toolchain.toml`).
3. Bypass nono for `op://` / `apple-password://`: write a
   `local_load_from_op` / `local_load_from_apple_password` in
   `host/keystore.rs` that mirrors nono's behavior but uses
   `Command::new(absolute_path).env_clear().envs(allowed)`. Cuts the
   PATH-hijack vector (trust-root F3) and the env-wholesale vector
   (iso F-iso-3) in one change.

(3) is a deviation from the original spike's "let nono handle it"
shape but is the only way to keep the substrate's trust contract.

Source findings: trust-root F1 (P1), F3 (P1), F4 (P2), isolation
F-iso-3 (P2).

### Cross-cut E — "Health endpoints decoupled from load-bearing paths"

silence-friend Gap 4 + oracle-friend F3: `/healthz` returns
`ok=true` if the Worker boots, ignoring whether nono can actually
reach `op` / `security` / the keychain daemon. AND `/healthz` is
unauthenticated, exposing the `platform` field. Both are pre-existing
patterns the swap didn't introduce, but the swap *makes the deep-probe
absence costlier* — a fresh apko image with no `op` CLI returns
green `/healthz` while every `/sign` 503s.

**Cross-cut prescription.** Out of scope for this cycle's fix
budget — the deep-probe design needs a probe URL convention and
careful trust-boundary thinking (must not signal scheme existence to
unauthenticated callers). File as `cloister-future-deep-healthz`
follow-up bead. Document the gap in threat-model §17 with explicit
fix-on-follow-up status (NOT deferred — actively tracked).

Source findings: silence Gap 4 (P1), oracle F3 (P3).
